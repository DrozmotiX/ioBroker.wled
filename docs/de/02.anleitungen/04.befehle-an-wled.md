## Wie sende ich einen kompletten JSON-Befehl an WLED aus ioBroker?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=segments-commands-01; features=state-action-json,state-write-transport -->
<!-- muss beantworten: Erklärt den action-Datenpunkt, das Format der WLED-JSON-API und den Unterschied zu rawCommand. -->

**Kurz:** Schreib den JSON-Befehl als Text in `wled.0.<Gerät>.action`, zum Beispiel `{"on":true,"bri":128,"seg":[{"id":0,"fx":9}]}`. Der Adapter schickt ihn unverändert an die JSON-API des Geräts. Das ist der empfohlene Weg, wenn du mehrere Werte auf einmal ändern willst.
<!-- quelle: code=main.js:162-171@v0.9.2; code=main.js:405-427@v0.9.2; code=lib/stateAttr.js:4-9@v0.9.2; interview=10; forum=1340784; forum=1311327; forum=701436 -->

### So gehst du vor

1. Öffne im Objektbaum `wled.0.<Gerät>.action`.
2. Schreib einen gültigen JSON-Text hinein, zum Beispiel `{"on":true,"bri":128}`.
3. Prüf das Ergebnis am Gerät oder an den Datenpunkten `on` und `bri`, die WLED danach zurückmeldet.
<!-- quelle: code=main.js:162-171@v0.9.2; code=main.js:405-427@v0.9.2 -->

Im Skript sieht das so aus:

```js
setState('wled.0.<Gerät>.action', JSON.stringify({
    on: true,
    bri: 128,
    seg: [{ id: 0, fx: 9, col: [[255, 120, 0]] }],
}));
```
<!-- quelle: code=main.js:162-171@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

`JSON.stringify` macht aus dem Objekt den Text, den `action` erwartet. Ein Objekt direkt in den Datenpunkt zu schreiben funktioniert nicht.
<!-- quelle: code=main.js:163-169@v0.9.2; code=lib/stateAttr.js:4-9@v0.9.2 -->

<!-- bild: screenshot Objektbaum, JSON-Text in wled.0.<MAC>.action schreiben (nach Admin-Neubau) -->

### Das Format der WLED-JSON-API

Der Befehl ist ein Teil des Zustandsobjekts von WLED. Du schreibst nur die Werte hinein, die sich ändern sollen. Häufige Beispiele:
<!-- quelle: extern=WLED-Docs:docs/interfaces/json-api.md -->

| Was | JSON |
|---|---|
| Einschalten mit halber Helligkeit | `{"on":true,"bri":128}` |
| Umschalten | `{"on":"t"}` |
| Preset 3 laden, auch wenn es schon aktiv war | `{"on":true,"ps":3}` |
| Effekt und Palette in Segment 1 | `{"seg":[{"id":1,"fx":9,"pal":5}]}` |
| Primärfarbe in Segment 0 | `{"seg":[{"id":0,"col":[[255,0,0]]}]}` |
| In 5 Sekunden ausblenden | `{"on":false,"tt":50}` |
| Nightlight, 10 Minuten | `{"nl":{"on":true,"dur":10,"mode":1}}` |
<!-- quelle: extern=WLED-Docs:docs/interfaces/json-api.md; extern=WLED:wled00/json.cpp:331-363@v0.15.0 -->

Alle Schlüssel stehen in der [JSON-API-Doku von WLED](https://kno.wled.ge/interfaces/json-api/). WLED selbst empfiehlt die JSON-API für neue Anbindungen und nicht mehr die ältere HTTP-API.
<!-- quelle: extern=WLED-Docs:docs/interfaces/json-api.md; extern=WLED-Docs:docs/interfaces/http-api.md; interview=10 -->

### Was der Adapter damit macht

- Er prüft nur, ob der Text gültiges JSON ist. Ist er es nicht, steht `State … is not a valid JSON string` als Fehler im Log und nichts wird gesendet.
- Den Inhalt prüft er nicht. Schreibst du einen Schlüssel falsch, ignoriert WLED ihn ohne Meldung.
- Er sendet über die WebSocket-Verbindung, wenn sie steht, sonst per HTTP-POST an `http://192.168.x.y/json`.
<!-- quelle: code=main.js:162-171@v0.9.2; code=main.js:405-427@v0.9.2; code=main.js:1436-1452@v0.9.2 -->

**Bis v0.9.2:** Über WebSocket setzt der Adapter `action` nie auf `ack=true`. Über HTTP setzt er `ack=true`, wenn WLED `success` meldet.
<!-- quelle: code=main.js:407-427@v0.9.2 -->

**Ab v0.9.3:** Der Adapter setzt `ack=true`, sobald der Befehl gesendet ist, und warnt im Log, wenn das Senden scheitert. An ein Gerät, das offline ist, sendet er nichts ([#904](https://github.com/DrozmotiX/ioBroker.wled/issues/904)).
<!-- quelle: code=main.js:400-421@v0.9.3; issue=#904 -->

### action oder rawCommand?

| | `action` | `rawCommand` |
|---|---|---|
| Format | JSON, zum Beispiel `{"bri":128}` | HTTP-Parameter, zum Beispiel `A=128` |
| API von WLED | JSON-API (`/json`) | ältere HTTP-API (`/win`) |
| Segmente, Presets, einzelne LEDs | ja | nur eingeschränkt |
| Verbindung | WebSocket oder HTTP | immer HTTP |
<!-- quelle: code=main.js:162-217@v0.9.2; extern=WLED-Docs:docs/interfaces/http-api.md; extern=WLED-Docs:docs/interfaces/json-api.md; interview=10 -->

Nimm `action`, wann immer es geht. `rawCommand` ist für Befehle gedacht, die du schon als HTTP-API-Text hast, siehe [Wie sende ich rohe WLED-HTTP-API-Befehle (rawCommand)?](#send-raw-wled-http-api).
<!-- quelle: interview=10 -->

> [!NOTE]
> `action` gibt es ab Adapter-Version 0.8.0. Fehlt der Datenpunkt bei dir, aktualisiere den Adapter.
<!-- quelle: code=main.js:886@v0.9.2; code=README.md:160@v0.9.2 -->

**Ab v0.10.0:** Kommt `action` kurz nach anderen Schreibzugriffen auf dasselbe Gerät, fasst der Adapter alles zu einem Befehl zusammen. Werte aus `action` überschreiben dabei gleichnamige Werte, die vorher geschrieben wurden ([#926](https://github.com/DrozmotiX/ioBroker.wled/issues/926)).
<!-- quelle: code=main.js:463-490@v0.10.0; code=main.js:581-603@v0.10.0; issue=#926 -->

## Wie sende ich JSON per Skript (axios oder httpPost) direkt an WLED?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=segments-commands-02; features=state-action-json -->
<!-- muss beantworten: Zeigt ein Skriptbeispiel und nennt, wann der Weg über den Adapter vorzuziehen ist. -->

**Kurz:** Im JavaScript-Adapter schickst du das JSON mit `httpPost` oder `axios` an `http://192.168.x.y/json/state`. Einfacher und robuster ist es aber, denselben JSON-Text in `wled.0.<Gerät>.action` zu schreiben. Dann sendet der Adapter, und du brauchst die IP-Adresse im Skript nicht.
<!-- quelle: code=main.js:162-171@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md; extern=ioBroker.javascript:docs/en/javascript.md; forum=1247485; forum=642640 -->

### Mit httpPost

`httpPost` gibt es im JavaScript-Adapter ab Version 7.9.0. Es schickt ein Objekt als JSON:

```js
httpPost('http://192.168.x.y/json/state', { on: true, bri: 128, seg: [{ id: 0, fx: 9 }] }, (error, response) => {
    if (error) {
        log(`WLED nicht erreichbar: ${error}`, 'warn');
        return;
    }
    log(`Antwort: ${JSON.stringify(response.data)}`);
});
```
<!-- quelle: extern=ioBroker.javascript:docs/en/javascript.md; extern=WLED-Docs:docs/interfaces/json-api.md -->

WLED antwortet mit `{"success":true}`. Schickst du `"v":true` mit, kommt stattdessen der ganze neue Zustand zurück.
<!-- quelle: extern=WLED-Docs:docs/interfaces/json-api.md -->

### Mit axios

`axios` ist im JavaScript-Adapter schon geladen, du musst es nicht installieren:

```js
const axios = require('axios');

async function wled(befehl) {
    try {
        const antwort = await axios.post('http://192.168.x.y/json/state', befehl, { timeout: 3000 });
        return antwort.data;
    } catch (error) {
        log(`WLED nicht erreichbar: ${error.message}`, 'warn');
    }
}

wled({ on: true, bri: 128 });
```
<!-- quelle: extern=ioBroker.javascript:docs/en/javascript.md; extern=WLED-Docs:docs/interfaces/json-api.md; forum=642640 -->

### Wann der Weg über den Adapter besser ist

Mit `setState('wled.0.<Gerät>.action', JSON.stringify(befehl))` erreichst du dasselbe. Das hat Vorteile:
<!-- quelle: code=main.js:162-171@v0.9.2; interview=10 -->

- **Keine IP im Skript.** Der Adapter kennt die Adresse des Geräts und hat sie am Geräteobjekt gespeichert. Du sprichst das Gerät nur über seine ID an.
- **Bestehende Verbindung.** Der Adapter nutzt die WebSocket-Verbindung, die ohnehin offen ist. Ein eigener HTTP-Aufruf ist eine zusätzliche Verbindung zum Gerät.
- **Einheitliche Fehlerbehandlung.** **Ab v0.9.3** verwirft der Adapter Befehle an Geräte, die offline sind, mit einer klaren Warnung im Log ([#904](https://github.com/DrozmotiX/ioBroker.wled/issues/904)).
<!-- quelle: code=main.js:844-857@v0.9.2; code=main.js:398-404@v0.9.2; code=main.js:405-427@v0.9.2; code=main.js:400-421@v0.9.3; issue=#904; interview=10 -->

Den direkten Weg brauchst du nur, wenn du die Antwort von WLED auswerten willst oder einen anderen Endpunkt als `/json/state` ansprichst.
<!-- quelle: extern=WLED-Docs:docs/interfaces/json-api.md -->

> [!NOTE]
> Auch wenn du direkt an WLED sendest, aktualisiert der Adapter seine Datenpunkte. Ist er per WebSocket verbunden, meldet WLED ihm jede Änderung von selbst, egal woher sie kommt. Ohne WebSocket kommt die Änderung mit der nächsten Abfrage.
<!-- quelle: extern=WLED-Docs:docs/interfaces/websocket.md; code=main.js:1339-1381@v0.9.2 -->
