## Was bedeuten die einzelnen WLED-Datenpunkte?

<!-- abschnitt: prio=B; gewicht=1; readme=missing; cluster=control-basics-18; features=state-attribute-library,state-root-light,state-segments -->
<!-- muss beantworten: Gibt eine Tabelle aller Datenpunkte mit Typ, Schreibbarkeit, Bedeutung und Wertebereich. -->

**Kurz:** Die Datenpunkte spiegeln die JSON-API von WLED. Fast jeder Schlüssel, den das Gerät meldet, wird ein Datenpunkt mit demselben Namen. Dazu kommen einige Datenpunkte, die der Adapter selbst anlegt, zum Beispiel `action` und `psave`. Die Tabellen unten nennen Typ, Schreibbarkeit, Bedeutung und Wertebereich.
<!-- quelle: code=main.js:1024-1136@v0.9.2; code=main.js:881-887@v0.9.2; code=lib/stateAttr.js:1-634@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

Welche Datenpunkte es bei dir gibt, hängt von deiner WLED-Firmware ab. Der Adapter legt an, was das Gerät meldet. Name, Typ, Rolle und Schreibbarkeit holt er aus seiner Liste bekannter Schlüssel (`lib/stateAttr.js`). Kennt er einen Schlüssel nicht, legt er ihn trotzdem an, aber nur lesbar und mit dem Typ des Werts. Schreibst du einen Datenpunkt als Steuerbefehl (`ack=false`), schickt der Adapter ihn unter demselben Schlüssel an WLED.
<!-- quelle: code=main.js:1533-1563@v0.9.2; code=main.js:146-150@v0.9.2; code=main.js:218-222@v0.9.2; code=main.js:384-391@v0.9.2 -->

Alle IDs beginnen mit `wled.0.<Gerät>`, wobei `<Gerät>` die MAC-Adresse des Geräts ohne Doppelpunkte ist. Die Spalte „Schreiben“ sagt, ob der Adapter einen geschriebenen Wert an das Gerät schickt.
<!-- quelle: code=main.js:1124-1128@v0.9.2; code=lib/stateAttr.js:1-634@v0.9.2 -->

### Direkt unter dem Gerät

| Datenpunkt | Typ | Schreiben | Bedeutung | Werte |
|---|---|---|---|---|
| `on` | boolean | ja | Hauptschalter des Geräts | `true` / `false` |
| `bri` | number | ja | Gesamthelligkeit | 0 bis 255 |
| `transition` | number | ja | Überblendzeit bei Farb- und Helligkeitswechseln, in 100 ms | 0 bis 65535, `7` = 700 ms |
| `tt` | mixed | ja | Überblendzeit nur für den nächsten Befehl, in 100 ms | 0 bis 65535 |
| `ps` | number | ja | aktives Preset; schreiben lädt ein Preset | -1 bis 250, `-1` = keins |
| `psave` | mixed | ja | speichert den aktuellen Zustand als Preset | 1 bis 250 |
| `pl` | number | ja, wirkt aber nicht | laufende Playlist (nur Anzeige) | -1 bis 250, `-1` = keine |
| `mainseg` | number | ja | Hauptsegment, das UDP-Sync und Befehle ohne Segmentnummer nutzen | 0 bis Segmentzahl - 1 |
| `lor` | number | ja | Live-Override: Echtzeitdaten übersteuern | `0` aus, `1` bis zum Ende der Live-Daten, `2` bis zum Neustart |
| `time` | mixed | nein | Uhrzeit setzen (Befehl ohne Rückmeldung) | Unix-Zeit in Sekunden |
| `action` | string | ja | kompletter JSON-Befehl an WLED | JSON-Text, z. B. `{"on":true,"bri":128}` |
| `rawCommand` | string | ja | Befehl an die alte HTTP-API (`/win`) | Text, z. B. `T=2&A=128` |
<!-- quelle: code=lib/stateAttr.js:4-15@v0.9.2; code=lib/stateAttr.js:52-78@v0.9.2; code=lib/stateAttr.js:105-109@v0.9.2; code=lib/stateAttr.js:133-142@v0.9.2; code=lib/stateAttr.js:450-463@v0.9.2; code=main.js:881-887@v0.9.2; code=main.js:160-213@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

`tt`, `psave`, `time`, `action` und `rawCommand` meldet WLED nicht zurück. Der Adapter legt sie selbst an, ihr Wert zeigt nur, was zuletzt geschrieben wurde.

### Segmente (`seg.<Segment>`)

Für jedes Segment gibt es einen Kanal `seg.<Segment>`. Das erste Segment hat die Nummer `0`.
<!-- quelle: code=main.js:1007-1043@v0.9.2 -->

| Datenpunkt | Typ | Schreiben | Bedeutung | Werte |
|---|---|---|---|---|
| `id` | number | nein | Nummer des Segments | 0 bis Segmentzahl - 1 |
| `n` | string | ja | Name des Segments | Text |
| `start` | number | ja | erste LED des Segments | 0 bis LED-Zahl - 1 |
| `stop` | number | ja | LED nach dem Segment (nicht mehr enthalten) | 0 bis LED-Zahl |
| `len` | number | ja | Länge (`stop` - `start`) | 0 bis LED-Zahl |
| `grp` | number | ja | Gruppierung: so viele LEDs zeigen dieselbe Farbe | 0 bis 255 |
| `spc` | number | ja | Abstand: so viele LEDs bleiben zwischen den Gruppen aus | 0 bis 255 |
| `of` | number | ja | Versatz: verschiebt den Anfang des Effekts | -Länge + 1 bis Länge |
| `on` | boolean | ja | Segment ein/aus | `true` / `false` |
| `bri` | number | ja | Helligkeit des Segments | 0 bis 255 |
| `cct` | number | ja | Farbtemperatur des Weißanteils | 0 bis 255 oder 1900 bis 10091 K |
| `frz` | boolean | ja | Effekt anhalten (einfrieren) | `true` / `false` |
| `col.0`, `col.1`, `col.2` | mixed | ja | Primär-, Sekundär- und Tertiärfarbe als RGB-Text | `[255,0,0]` oder `[255,0,0,0]` mit Weiß |
| `col.0_HEX`, `col.1_HEX`, `col.2_HEX` | mixed | ja | dieselben Farben als HEX | `#rrggbb` oder `#rrggbbww` |
| `fx` | number | ja | Effekt, mit Namensliste | Nummer, 0 bis Effektzahl - 1 |
| `sx` | number | ja | Geschwindigkeit des Effekts | 0 bis 255 |
| `ix` | number | ja | Intensität des Effekts | 0 bis 255 |
| `pal` | number | ja | Palette, mit Namensliste | Nummer |
| `c1`, `c2`, `c3` | string | ja | Zusatzregler des Effekts | `c1`, `c2`: 0 bis 255, `c3`: 0 bis 31 |
| `o1`, `o2`, `o3` | boolean | nein | Zusatzschalter des Effekts | `true` / `false` |
| `sel` | boolean | ja | Segment ist ausgewählt | `true` / `false` |
| `rev` | boolean | ja | Effekt läuft rückwärts | `true` / `false` |
| `mi` | boolean | nein (ab v0.9.3 ja) | Segment spiegeln | `true` / `false` |
| `si` | number | nein | Klangsimulation für Audio-Effekte | 0 bis 3 |
| `m12` | number | nein | „Expand 1D FX“ bei Matrizen | 0 bis 4 |
| `set` | number | nein | Gruppe des Segments in der WLED-Oberfläche | 0 bis 3 |
<!-- quelle: code=lib/stateAttr.js:25-42@v0.9.2; code=lib/stateAttr.js:127-131@v0.9.2; code=lib/stateAttr.js:150-269@v0.9.2; code=lib/stateAttr.js:500-503@v0.9.2; code=lib/stateAttr.js:508-550@v0.9.2; code=lib/stateAttr.js:575-585@v0.9.2; code=main.js:1036-1111@v0.9.2; code=main.js:241-391@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

Ein geschriebener Segment-Datenpunkt geht als `{"seg":{"id":<Segment>,"<Schlüssel>":<Wert>}}` an WLED. Schreibst du eine Farbe, schickt der Adapter alle drei Farben des Segments mit. Matrix-Schlüssel wie `startY`, `stopY`, `rY`, `mY` und `tp` kennt der Adapter nicht, sie erscheinen bei 2D-Aufbauten nur lesbar.
<!-- quelle: code=main.js:241-391@v0.9.2; code=main.js:1533-1563@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

**Ab v0.9.3:** `seg.<Segment>.mi` ist schreibbar ([#918](https://github.com/DrozmotiX/ioBroker.wled/issues/918)). Die Segment-Kanäle tragen die Segment-ID aus WLED, und Segmente, die du in WLED anlegst oder löschst, zieht der Adapter ohne Neustart nach ([#909](https://github.com/DrozmotiX/ioBroker.wled/issues/909)).
<!-- quelle: code=lib/stateAttr.js:500-506@v0.9.3; issue=#918; issue=#909 -->

## Wie schreibe ich die Effekt-Parameter c1 bis c3?

<!-- abschnitt: prio=B; gewicht=1; readme=missing; cluster=effects-presets-14; features=state-segments -->
<!-- muss beantworten: Nennt die Datenpunkte und ab welcher Version sie beschreibbar sind. -->

**Kurz:** Die Zusatzregler eines Effekts liegen je Segment unter `wled.0.<Gerät>.seg.<Segment>.c1`, `c2` und `c3`. Du schreibst sie wie jeden anderen Segment-Datenpunkt als Steuerbefehl mit einer Zahl. Schreibbar sind sie ab v0.7.3, im Grundstand v0.9.2 also immer.
<!-- quelle: code=lib/stateAttr.js:533-550@v0.9.2; code=main.js:384-391@v0.9.2; issue=#688 -->

In der WLED-Oberfläche erscheinen diese Regler unter wechselnden Namen, je nach Effekt. Beim Effekt „Scrolling Text“ zum Beispiel heißt `c1` „Trail“. Welcher Regler bei welchem Effekt was bewirkt und ob er überhaupt genutzt wird, legt die Firmware für jeden Effekt fest.
<!-- quelle: issue=#688; extern=WLED-Docs:docs/interfaces/json-api.md -->

| Datenpunkt | Werte | Bedeutung |
|---|---|---|
| `seg.<Segment>.c1` | 0 bis 255 | Zusatzregler 1 des Effekts |
| `seg.<Segment>.c2` | 0 bis 255 | Zusatzregler 2 des Effekts |
| `seg.<Segment>.c3` | 0 bis 31 | Zusatzregler 3 des Effekts |
<!-- quelle: code=lib/stateAttr.js:533-550@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md; extern=WLED:wled00/json.cpp:252-255@v0.15.0 -->

### So gehst du vor

1. Stell in WLED den Effekt ein und schau in der WLED-Oberfläche, welcher Regler welchen Namen hat. Der erste Zusatzregler nach Geschwindigkeit und Intensität ist `c1`.
2. Schreib den Wert als Steuerbefehl, zum Beispiel `setState('wled.0.<Gerät>.seg.0.c1', 0);`.
3. Der Regler in der WLED-Oberfläche springt auf den neuen Wert.
<!-- quelle: code=main.js:384-391@v0.9.2; issue=#688; extern=WLED-Docs:docs/interfaces/json-api.md -->

Der Adapter schickt dann `{"seg":{"id":0,"c1":0}}` an das Gerät. WLED nimmt die Zahl auch als Text an, `"0"` wirkt also genauso.
<!-- quelle: code=main.js:384-391@v0.9.2; extern=WLED:wled00/json.cpp:252-255@v0.15.0; extern=WLED:wled00/util.cpp:56-69@v0.15.0 -->

> [!NOTE]
> `c1` bis `c3` haben im Adapter den Typ `string`, WLED meldet aber Zahlen. Darum kann ioBroker beim Aktualisieren eine Warnung zum Datentyp ins Log schreiben („has to be type "string" but received type "number"“). Sie ist harmlos, die Werte kommen trotzdem an.
<!-- quelle: code=lib/stateAttr.js:533-550@v0.9.2; code=main.js:1591-1594@v0.9.2; extern=ioBroker.js-controller:packages/adapter/src/lib/adapter/validator.ts:86-110@v7.0.7 -->

### Die Schalter o1 bis o3

Neben den Reglern haben manche Effekte bis zu drei Zusatzschalter, `o1` bis `o3`. Der Adapter zeigt sie unter `seg.<Segment>.o1` bis `o3` an, schickt geschriebene Werte aber nicht an das Gerät. Willst du einen Schalter setzen, nimm den Datenpunkt `action` mit einem JSON-Befehl:

```js
setState('wled.0.<Gerät>.action', JSON.stringify({ seg: { id: 0, o1: true } }));
```
<!-- quelle: code=lib/stateAttr.js:518-532@v0.9.2; code=main.js:160-170@v0.9.2; extern=WLED-Docs:docs/interfaces/json-api.md -->

**Bis v0.7.2:** `c1` bis `c3` waren nur lesbar. Ab v0.7.3 sind alle Segment-Datenpunkte mit Schreibrecht beschreibbar, darunter `c1` bis `c3` ([#688](https://github.com/DrozmotiX/ioBroker.wled/issues/688)).
<!-- quelle: code=lib/stateAttr.js:434-437@v0.7.2; code=lib/stateAttr.js:439-443@v0.7.3; issue=#688; issue=#706 -->
