## What does the warning "State attribute definition missing" mean?

<!-- abschnitt: prio=A; gewicht=11; readme=missing; cluster=logs-install-01; features=log-missing-attribute,state-attribute-library -->
<!-- muss beantworten: Erklärt, dass es nur eine Debug-Meldung zu unbekannten Feldern ist, und ab welcher Version. -->

**In short:** The message is harmless; you don't need to do anything. WLED delivers a field for which the adapter has no description of its own. The adapter creates the state anyway. Since v0.7.1 the message only appears at the log level "debug".
<!-- quelle: code=main.js:1544-1548@v0.9.2; code=main.js:1558-1563@v0.9.2; code=CHANGELOG_OLD.md:6@v0.9.2 -->

This is what the message looks like:

```text
State attribute definition missing for : <field> with value : <value>
```
<!-- quelle: code=main.js:1547@v0.9.2 -->

### What is behind it

The adapter has a list of all WLED fields it knows. For each field, the list holds the name, the data type, the role and whether you may write the state. If a new WLED firmware brings a field that is missing from the list, the adapter creates the state like this:

- The name is the field name from WLED.
- The data type follows the value WLED delivers.
- The state is read-only. You can't write through this state.
<!-- quelle: code=main.js:1544-1563@v0.9.2; code=lib/stateAttr.js:1-60@v0.9.2 -->

Examples from the past are `cct`, `n` and `liveseg`. They came with new WLED versions and are in the list by now.
<!-- quelle: issue=#322; issue=#423; issue=#479; code=CHANGELOG_OLD.md:2-6@v0.9.2 -->

If you want to set such a field anyway, send it as a JSON command via the `action` state. If a field is missing for good, report it in a [GitHub issue](https://github.com/DrozmotiX/ioBroker.wled/issues).
<!-- quelle: code=main.js:181-190@v0.9.3; issue=#15; issue=#487 -->

### Older versions

**Up to v0.7.0:** The message appeared as a warning or error in the normal log, sometimes with the addition `Sentry disabled, error caught`. In v0.5.x the instance could stop afterwards. In that case, update the adapter.
<!-- quelle: issue=#44; issue=#322; issue=#423; code=CHANGELOG_OLD.md:6@v0.9.2 -->

**Up to v0.9.2:** At the level "debug", the message appears in the log again on every update from the device, over and over for the same field.
<!-- quelle: code=main.js:1544-1548@v0.9.2; issue=#917 -->

**From v0.9.3:** The adapter reports each missing field only once per start ([#917](https://github.com/DrozmotiX/ioBroker.wled/issues/917)).
<!-- quelle: issue=#917; code=main.js:1724-1730@v0.9.3 -->

**See also:** [How do I send a complete JSON command to WLED from ioBroker?](../02.anleitungen/04.befehle-an-wled.md#send-complete-json-command-wled) · [Why does the adapter stop working after a WLED firmware update?](../04.fehlerbehebung/01.verbindung-und-start.md#adapter-stop-working-after-wled)

## What do warnings about a wrong data type or a missing "val" mean when writing states?

<!-- abschnitt: prio=A; gewicht=12; readme=missing; cluster=logs-install-05,logs-install-16,control-basics-10; features=info-device-online-state,migration-online-boolean,state-value-handling,state-root-light,state-segment-colors -->
<!-- muss beantworten: Erklärt erwartete Datentypen für on, ps und Farben und wie Blockly die Werte übergibt. -->

**In short:** ioBroker checks every value written to a state against the state's data type. If the type doesn't match, the log shows a warning. If it comes from your script, you are writing the value in the wrong type, for example `"true"` as text instead of `true`. If it comes from the adapter itself, an update helps.
<!-- quelle: issue=#611; issue=#189; issue=#11; issue=#52 -->

This is what the messages look like:

```text
State value to set for "wled.0.<MAC>.<State>" has to be type "boolean" but received type "string"
State value to set for "wled.0.<MAC>.<State>" has to be one of type "string", "number", "boolean" but received type "object"
State value to set is invalid for wled.0.<MAC>.<State>: The state is missing the required property val!
```
<!-- quelle: issue=#611; issue=#189; issue=#11 -->

The start of the log line shows who wrote the value. If it says `wled.<instance>`, the value comes from the adapter. If it says, for example, `javascript.0`, it comes from your script.
<!-- quelle: issue=#611; issue=#11 -->

### Which data type do the states expect?

| State | Type | Example |
|---|---|---|
| `on` | boolean | `true` or `false` |
| `bri` | number | `0` to `255` |
| `ps` | number | `3` for preset 3 |
| `pl` | number | `1` for playlist 1 |
| `transition` | number | `7` |
| `seg.<segment>.col.0`, `.1`, `.2` | text with numbers in square brackets | `"[255,0,0]"` or with white channel `"[255,0,0,0]"` |
| `seg.<segment>.col.0_HEX`, `.1_HEX`, `.2_HEX` | text | `"#ff0000"` |
| `action` | text containing JSON | `{"on":true,"bri":128}` as text |
| `_info._online` | boolean, read-only | `true` or `false` |
<!-- quelle: code=main.js:1559@v0.9.2; code=lib/stateAttr.js:52-78@v0.9.2; code=lib/stateAttr.js:222-257@v0.9.2; code=lib/stateAttr.js:277-281@v0.9.2; code=main.js:1080-1090@v0.9.2; code=main.js:1590-1594@v0.9.2; code=main.js:181-190@v0.9.3 -->

The adapter sets the types of `on`, `bri`, `ps`, `pl` and `transition` when it creates them, based on the value WLED delivers. The color states are of type "mixed" and hold the color as text. When writing, the adapter also accepts `"255,0,0"` without brackets.
<!-- quelle: code=main.js:1559@v0.9.2; code=lib/stateAttr.js:222-257@v0.9.2; code=main.js:312-330@v0.9.2 -->

### How to write the values in the right type

In a script, pass numbers and booleans without quotes, and colors as text:

```js
setState('wled.0.<MAC>.on', true);                  // not 'true'
setState('wled.0.<MAC>.bri', 128);                  // not '128'
setState('wled.0.<MAC>.ps', 3);                     // not '3'
setState('wled.0.<MAC>.seg.0.col.0', '[255,0,0]');  // text, not an array
setState('wled.0.<MAC>.seg.0.col.0_HEX', '#ff0000');
```
<!-- quelle: code=lib/stateAttr.js:52-78@v0.9.2; code=lib/stateAttr.js:222-257@v0.9.2; issue=#52 -->

In Blockly, the block you attach to "control" or "update" decides the type:

1. For `on`, use the logic block "true" or "false". A text block containing `true` delivers text.
2. For `bri`, `ps` and `pl`, use the number block from "Math". A text block containing `3` delivers text.
3. For colors, use a text block with `[255,0,0]` or `#ff0000`. A list block delivers a list, so the type "object".
<!-- quelle: issue=#52; forum=429968; issue=#189 -->

![Overview: the logic block "true" or "false" delivers a boolean for on. The number block delivers a number for bri, ps, pl and transition. A text block delivers text for the color states. A text block with true on on, and a list block on a color, lead to a warning.](img/datentypen.svg)
<!-- quelle: code=main.js:1559@v0.9.2; code=lib/stateAttr.js:52-78@v0.9.2; code=lib/stateAttr.js:222-257@v0.9.2; issue=#52; issue=#189; issue=#611 -->

### Messages from the adapter itself

**Up to v0.9.2:** If a device can't be reached, the adapter writes `_info._online` as text. The log then shows `State value to set for "wled.0.<MAC>._info._online" has to be type "boolean" but received type "string"`. You don't need to change anything; the message comes from the adapter.
<!-- quelle: code=main.js:1387-1392@v0.9.2; code=main.js:1590-1594@v0.9.2; issue=#788; issue=#794 -->

**From v0.9.3:** `_info._online` is always a boolean, and the message no longer appears ([#788](https://github.com/DrozmotiX/ioBroker.wled/issues/788), [#794](https://github.com/DrozmotiX/ioBroker.wled/issues/794)).
<!-- quelle: issue=#788; issue=#794; code=main.js:1546-1562@v0.9.3 -->

The message `The state is missing the required property val!` and type messages about states under `_info` such as `_info.mac` came from adapter versions from 2020 and 2021. Today the adapter skips empty values. If you still see these messages, update the adapter.
<!-- quelle: issue=#11; issue=#189; code=main.js:1590-1594@v0.9.2 -->

### States that change with v0.9.3

**From v0.9.3:** `seg.<segment>.mi` (mirror segment) is a boolean and can be written ([#918](https://github.com/DrozmotiX/ioBroker.wled/issues/918)).
<!-- quelle: issue=#918; code=lib/stateAttr.js:501-506@v0.9.3; code=lib/stateAttr.js:500-503@v0.9.2 -->

**From v0.9.3:** `time` is a number (Unix timestamp) and can be written to set the device's clock ([#919](https://github.com/DrozmotiX/ioBroker.wled/issues/919)). Up to v0.9.2, `time` is of type "mixed" and read-only.
<!-- quelle: issue=#919; code=lib/stateAttr.js:450-455@v0.9.3; code=lib/stateAttr.js:450-454@v0.9.2 -->
